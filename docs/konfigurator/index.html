Attesta Zyklus: Konfigurator

Erzeugt Profil, Workflow und Issue-Formular vollstaendig in diesem Browser. Nach dem Laden dieser Seite verlaesst keine Anfrage deinen Rechner in Richtung des Betreibers, und nichts wird hier dauerhaft gespeichert: ein Neuladen leert alle Felder.

Kein Feld fuer einen Lizenzschluessel. Der Schluessel gehoert als Repository-Geheimnis ATTESTA_LIZENZSCHLUESSEL unter Settings, Secrets and variables, Actions in dein eigenes Repository, niemals auf eine fremde Seite.

# kritikalitaet-delegation.yaml

version: 1.0.0
kritikalitaet:
  K1:
    label: K1 leicht
    definition: Fehler ist folgenlos oder trivial reversibel
    typische_faelle:
      - interne Tools
      - Prototypen
      - UI-Kosmetik
      - Doku
  K2:
    label: K2 standard
    definition: Fehler stoert Nutzer oder Geschaeft, ist aber behebbar
    typische_faelle:
      - Kundenfeatures
      - Standard-Businesslogik
      - Reports
  K3:
    label: K3 kritisch
    definition: Fehler kostet Geld, Daten, Sicherheit oder Compliance
    typische_faelle:
      - Zahlungen
      - Auth
      - Datenmigration
      - irreversible Aktionen
      - personenbezogene Daten
      - regulierte Domaenen
einstufungsfragen:
  - Verarbeitet oder erzeugt das Arbeitspaket Geld, personenbezogene Daten oder Zugangsdaten? -> mindestens K3.
  - Ist ein Fehler ohne Datenverlust und ohne Nutzerauswirkung in Minuten rueckgaengig? -> K1.
  - Betrifft es Kundenvertrauen oder Geschaeftsprozesse, ist aber technisch reparierbar? -> K2.
  - Bleibt Unsicherheit? -> eine Stufe hoeher als der niedrigste plausible Wert.
delegation:
  S1:
    label: S1 Anweisen
    modus: eng gefuehrt
    ki_rolle: setzt exakt Spezifiziertes um
    mensch_rolle: spezifiziert vollstaendig, prueft jede Zeile
  S2:
    label: S2 Coachen
    modus: Entwurf plus enger Loop
    ki_rolle: erzeugt Entwuerfe, iteriert am Feedback
    mensch_rolle: prueft je Komponente
  S3:
    label: S3 Unterstuetzen
    modus: eigenstaendig in Spec-Grenzen
    ki_rolle: setzt eigenstaendig um
    mensch_rolle: prueft an Modulgrenze und Gate
  S4:
    label: S4 Delegieren
    modus: autonom in Leitplanken
    ki_rolle: setzt um, testet, prueft selbst vor
    mensch_rolle: prueft nur Ergebnis und Gates
guardrail_regel:
  bedingung: ohne maschinenlesbare Leitplanken (Coding-Standards, Contracts, automatisierte Tests, CI-Gates, Secret-Scanning)
  obergrenze: S2
  unabhaengig_von_k: true
reifegrundsatz: Reife wird erarbeitet (wiederholt zuverlaessige Ergebnisse), nicht angenommen. Absenkung ist jederzeit erlaubt.
max_delegation_je_kritikalitaet:
  label: Max. Delegation
  K1:
    wert: S4
  K2:
    wert: S3
  K3:
    wert: S2
    ausnahme:
      wert: S3
      voraussetzungen:
        - guardrails_vollstaendig
        - historie_nachgewiesen
      hinweis: S3 nur mit vollen Guardrails und nachgewiesener Historie

.github/workflows/attesta.yml

# Ersetze <ORG> durch den Marketplace-Eintrag, sobald er steht (siehe D1-7).
# Bis dahin: Fork oder Kopie dieses Repositorys referenzieren.
name: Attesta Zyklus

on:
  pull_request:
    types: [opened, synchronize, reopened]
  issues:
    types: [opened, edited]
  issue_comment:
    types: [created, edited]
  workflow_dispatch: {}
  schedule:
    # Nicht spezifiziert (SPEC-12): der genaue Tag im Monat. Vorschlag
    # "erster Werktag" ist in reinem Cron nicht ausdrueckbar, deshalb
    # vereinfacht auf den ersten Kalendertag.
    - cron: "0 6 1 * *"

permissions:
  contents: read
  issues: write
  pull-requests: write
  checks: write

jobs:
  attesta:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: <ORG>/attesta@v1
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          # Optional. Ohne Schluessel oder mit abgelaufenem Schluessel laeuft
          # attesta weiter, siehe REQ-35. Anlegen unter Settings, Secrets and
          # variables, Actions.
          lizenzschluessel: ${{ secrets.ATTESTA_LIZENZSCHLUESSEL }}
